# การเขียน/ตรวจเนื้อหาวิจัย เอกสารประกอบ และฉบับปกปิดตัวตน

ใช้กับงานประเภท A (เขียน), B (ตรวจและแก้เนื้อหา) และ D (เอกสารประกอบ) เท่านั้น
งานประเภท C (จัดรูปแบบอย่างเดียว) ห้ามแก้ตามไฟล์นี้ — ให้ **รายงาน** สิ่งที่พบเป็นข้อเสนอแยกจากไฟล์ผลลัพธ์

## 1. หลักฐานก่อนถ้อยคำ

- ทุกตัวเลข คะแนน จำนวนผู้ให้ข้อมูล วันที่ ต้องชี้กลับไปยังต้นทางที่ผู้ใช้ให้ได้
- ข้อมูลไม่ครบ → ไม่เติมเอง ใช้ตำแหน่งว่างที่ระบุชัด `[รอข้อมูล: …]` และใส่ในรายการข้อจำกัดของคำตอบ
- ค่าในแม่แบบ ภาพตัวอย่าง หรือโครงการเก่า ไม่ใช่ค่าตั้งต้นของงานใหม่ (จำนวนข้อกำหนด จำนวนชั้นสถาปัตยกรรม คะแนน ฯลฯ)

## 2. รายการตรวจความสอดคล้อง

- [ ] ชื่อเรื่องตรงกับสิ่งที่ทำและสิ่งที่ประเมินจริง (เช่น "ออกแบบ" ≠ "พัฒนาและทดสอบ")
- [ ] วัตถุประสงค์ ↔ วิธีวิจัย ↔ ผล ↔ อภิปราย ↔ สรุป ตอบกันครบทุกข้อ
- [ ] แยก ผลสำรวจ / ผลยืนยันข้อกำหนด / ผลประเมินสถาปัตยกรรม ออกจากกัน
- [ ] ระบุจำนวนผู้ให้ข้อมูล ขอบเขตเครื่องมือ และรอบประเมิน
- [ ] ไม่รวมคะแนนจากเครื่องมือคนละชุด เว้นแต่มีเหตุผลและวิธีคำนวณรองรับ
- [ ] ไม่เทียบคะแนนก่อน–หลังโดยตรงเมื่อรายการประเมินต่างกัน
- [ ] ไม่กล่าวว่า "ข้อกำหนดทุกข้อผ่าน" ถ้าประเมินเพียงบางกลุ่ม — ระบุว่ากลุ่มใด กี่ข้อ
- [ ] ไม่เรียกการเห็นชอบ 3 ใน 5 คน (ร้อยละ 60) ว่า "ผ่านเกณฑ์ร้อยละ 80" — คำนวณจากจำนวนจริงเสมอ
- [ ] แยกข้อที่ผ่านเกณฑ์ ออกจากข้อที่ผู้วิจัยปรับตามเสียงข้างมาก/ข้อเสนอแนะ
- [ ] แยก "ความเหมาะสมระดับแนวคิด" (ผู้เชี่ยวชาญประเมิน) ออกจาก "ประสิทธิภาพของระบบที่พัฒนาและทดสอบจริง"
- [ ] ข้อจำกัดและงานที่ต้องทดสอบต่อ เขียนตามหลักฐาน ไม่กล่าวเกิน

ร้อยละ/ค่าเฉลี่ยที่ปรากฏในเนื้อหา: คำนวณซ้ำจากข้อมูลต้นทางด้วยโค้ด ไม่คำนวณในใจ

## 3. งานข้อกำหนดระบบ (ตรวจเฉพาะองค์ประกอบที่งานนั้นมีจริง)

- ความเชื่อมโยง P–N–R (ปัญหา → ความต้องการ → ข้อกำหนด) ไม่มีข้อกำหนดลอย ไม่มีปัญหาที่ไม่ถูกรับ
- ประเภท DR / FR / NFR จัดถูก และรหัสไม่ซ้ำ ไม่ข้ามโดยไม่อธิบาย
- กลุ่มหน้าที่ และ MoSCoW (Must/Should/Could/Won't) สอดคล้องกับผลประเมิน
- กรอบ IPOF (Input–Process–Output–Feedback) และองค์ประกอบสถาปัตยกรรมอ้างข้อกำหนดได้
- ตารางตรวจสอบย้อนกลับ (traceability) ครบทั้งสองทิศ

## 4. เอกสารประกอบ / ภาคผนวก

- ย้ายรายละเอียดยาวไปเอกสารประกอบ **เมื่อผู้ใช้อนุญาตเท่านั้น** เช่น ผลประเมินรายข้อ ตารางย้อนกลับ เกณฑ์ยอมรับ กรณีทดสอบ
- งานจัดรูปแบบอย่างเดียว: ห้ามย้ายหรือลบภาคผนวกเอง
- เมื่อแยกไฟล์: ตรวจทุกการอ้าง "ตารางที่/รูปที่/ภาคผนวก" ในบทความใหม่ว่าชี้ถูก (เลขเดิมหรือข้อความ "ดูเอกสารประกอบ …") และเลขตาราง/รูปในบทความยังเรียง 1..n
- เอกสารอ้างอิงที่ใช้เฉพาะในภาคผนวก: จัดตามคู่มือหรือคำสั่งผู้ใช้ (รวมรายการหลัก หรือรายการแยก) แล้วรายงานว่าใช้แบบใด

## 5. ฉบับมีชื่อผู้แต่ง / ฉบับปกปิดตัวตน

สร้างตามคำขอ ไฟล์แยกกัน (เช่น `_author.docx`, `_blind.docx`)

ฉบับปกปิดตัวตน ตรวจ:
- [ ] ชื่อผู้แต่ง สังกัด อีเมล ORCID ที่อยู่ ผู้ประพันธ์บรรณกิจ
- [ ] กิตติกรรมประกาศ ทุนวิจัย เลขโครงการ ที่ระบุตัวตนได้
- [ ] ข้อความระบุตัวตนในเนื้อหา ("งานก่อนหน้าของผู้วิจัย [3]" → "งานใน [3]")
- [ ] หัว/ท้ายกระดาษ ชื่อไฟล์ ลายน้ำ
- [ ] คุณสมบัติไฟล์ author/last_modified_by (`apply_layout.py --anonymize-metadata`) คอมเมนต์ และ tracked changes (`docx_audit.py` รายงาน)
- [ ] **คง** ชื่อผู้แต่งในรายการอ้างอิงที่จำเป็น (การอ้างงานตนเองให้ทำตามคู่มือวารสาร)

หน้าคำแนะนำ รายการตรวจสอบ และบันทึกถึงผู้ใช้ ห้ามติดไปในฉบับส่งวารสาร
