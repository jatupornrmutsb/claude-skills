# IPOF + MoSCoW + สถาปัตยกรรม 7 ชั้น

ผลงานเป็นภาษาไทยเชิงวิชาการระดับบทความวารสารและสารนิพนธ์ป.โท ทุกตัวเลขต้องคำนวณจากข้อมูลจริงด้วยสคริปต์ และตรงกันทุกไฟล์

## เริ่มงานใหม่ — ถามก่อนเสมอ (ไม่เกิน 4 ข้อ เฉพาะที่ยังไม่รู้)

Skill นี้ **ไม่มีค่าตั้งต้น** ของ 4 เรื่องต่อไปนี้ ต้องถามผู้ใช้ทุกงานวิจัยใหม่ และห้ามใส่ค่าสมมติแทน

0. **ชื่อเรื่องวิจัย** (ถามข้อแรก) — ถ้าผู้ใช้แนบร่างบทความ/โครงร่าง/แบบประเมินมาแล้ว ให้อ่านชื่อเรื่องจากไฟล์แทนการถาม แล้วยืนยันกับผู้ใช้ครั้งเดียว ("ชื่อเรื่องคือ … ถูกต้องไหม") ชื่อที่ยืนยันแล้วคือชื่อที่ห้ามเปลี่ยนตลอดงาน
1. คำถามหลักของระบบ (ใช้ทดสอบข้อ Must ในขั้นที่ 4)
2. จำนวนผู้ตอบแบบสอบถาม (n) และจำนวนผู้เชี่ยวชาญ (k) — เกณฑ์ผ่าน = เห็นชอบ ≥ ร้อยละ 80 ของ k คำนวณเป็น ⌈0.8 × k⌉ (เช่น k = 5 ต้องเห็นชอบ 4 คน)
3. วารสารเป้าหมาย และคู่มือ/แม่แบบของวารสารนั้น (ถ้ามี)

ถามรวมในครั้งเดียว และข้ามข้อที่รู้แล้วจากไฟล์หรือบทสนทนา

ยังไม่ได้คำตอบ → ทำได้เฉพาะส่วนที่ไม่ขึ้นกับคำตอบ (เช่น ร่างข้อคำถาม) และระบุตำแหน่งว่าง `[รอข้อมูล: …]` ห้ามเดา
บันทึกคำตอบลง `project.json` (โครงสร้างใน `assets/examples/project.example.json`) ซึ่งเป็น **แหล่งข้อมูลเดียว** ของรหัส ข้อความ ระดับ ชั้น และเกณฑ์ยอมรับ แผนภาพ ตาราง และ Excel ต้องสร้างจากไฟล์นี้ `analyze.py validate` เตือนเมื่อ 4 เรื่องนี้ยังว่าง และ `prepub_check.py --project` เตือนเมื่อชื่อเรื่องในไฟล์ไม่ตรงกับชื่อที่บันทึกไว้

**ลำดับการใช้ข้อกำหนด**
1. คำสั่งล่าสุดของผู้ใช้
2. กฎเฉพาะงาน IPOF ใน Skill นี้ — อ้างแหล่งเดียวต่อข้อความ (ห้ามช่วง/หลายแหล่งในวงเล็บเดียว), ห้ามอ้างเว็บเพจ/บล็อก, ตารางในบทความ 4 + 1 ตาราง (ขั้นที่ 11), กฎการเขียนทั้งหมดด้านล่าง
3. คู่มือ/แม่แบบของวารสารที่ผู้ใช้ระบุ — ใช้สำหรับรูปแบบหน้า ฟอนต์ ความยาว และรูปแบบรายการอ้างอิง ถ้าคู่มือขัดกับกฎข้อ 2 ให้แจ้งจุดที่ขัดและถามผู้ใช้
4. ถ้าวารสารคือ JDTAIA และติดตั้ง Skill `jdtaia-ieee-document` ไว้ ใช้ Skill นั้นสำหรับรูปแบบหน้า การกระจายแบบไทย และการตรวจหน้า (กฎข้อ 2 ยังชนะ)

### สาระสำคัญที่ห้ามพลาดในแต่ละขั้น

- **ขั้น 2** X̄ และ S.D. แบบตัวอย่าง (n − 1) รายข้อ; รายด้านและภาพรวมจาก **คะแนนดิบทุกค่า** ห้ามเฉลี่ยค่าเฉลี่ย; คำถามเลือกหลายข้อ = จำนวนและร้อยละจากผู้ตอบทั้งหมด; แถวที่ไม่ติ๊ก/ติ๊กเกิน (`issues.csv`) ต้องตรวจกับต้นฉบับ ห้ามเดา
- **ขั้น 3** รวม N ที่ใช้ข้อมูลเดียวกัน/หน้าที่เดียวกันเป็นข้อกำหนดเดียวและบันทึกที่มา; เป้าหมาย ≤ 15–20 ข้อ, Must ≤ 6–8 ข้อ แต่ห้ามรวมจนเขียนเกณฑ์ยอมรับไม่ได้; ค่าเฉลี่ยข้อกำหนด = pooled คะแนนดิบของ N ที่รวม; NFR ไม่ผูกปัญหาใช้ "–"; CON มาจากคำตอบปลายเปิดและข้อเสนอแนะผู้เชี่ยวชาญ
- **ขั้น 4** เรียงค่าเฉลี่ยมากไปน้อย แบ่ง M/S/C ด้วยจุดแบ่งที่ระบุชัด (`moscow_cutoffs`); ทดสอบ Must ทุกข้อ "ถ้าไม่มีข้อนี้ ยังตอบคำถามหลักได้หรือไม่" ได้ → ลดเป็น Should; ข้อที่ Must ต้องใช้ → Must; Won't กำหนดจากขอบเขตรอบนี้และยังอยู่ในทะเบียน; ห้ามแก้ค่าเฉลี่ย บันทึกเหตุผลทุกข้อที่ระดับต่างจากคะแนน
- **ขั้น 5** ผู้เชี่ยวชาญชุดเดียวตลอดงาน; ไม่ผ่านเกณฑ์ → ปรับเป็นระดับที่ถูกเสนอมากที่สุด (เสมอ → ผู้วิจัยตัดสินพร้อมเหตุผล); เขียน "ถึงเกณฑ์ (4/5)" หรือ "ปรับตามเสียงข้างมาก (3/5)"; หลังยืนยัน ปรับถ้อยคำ Must ตามแบบประโยค + เกณฑ์ยอมรับเชิงปริมาณ + วิธีตรวจสอบ (Test/Analysis/Inspection/Demonstration)
- **ขั้น 6–7** ทุกกล่องมีรหัสและระดับฉบับสุดท้าย; ข้อกำหนดทุกข้ออยู่ในภาพ 7 ชั้น; Must ทุกข้อมีองค์ประกอบรับผิดชอบ; ช่วงใช้ "–"
- **ขั้น 8** ข้อเสนอที่นำไปปรับหลังประเมิน ระบุ "เพิ่มหลังการประเมิน"
- **ขั้น 9** ส่งแบบประเมินมาใหม่ → `analyze.py compare` รายงานข้อที่เปลี่ยนก่อนสร้างไฟล์ใหม่

## กฎการเขียน (บังคับทุกไฟล์) — รายละเอียด `references/writing-rules.md`

- ไม่ใช้ ":" ต่อจากข้อความภาษาไทย ยกเว้นป้ายตามแม่แบบวารสาร (เช่น "คำสำคัญ:")
- อ้างแหล่งเดียวต่อข้อความ ห้าม [1]–[3] หรือ [1, 2]; เรียงเลข IEEE ตามการอ้างครั้งแรก
- อ้างได้เฉพาะงานวิจัย/เอกสารที่ตีพิมพ์ ไม่ใช้เว็บเพจหรือบล็อก ตรวจทุกจุดกับ PDF ต้นฉบับที่ผู้ใช้โหลดมา (`references/citations.md`)
- คงคำว่าระดับแนวคิด/ต้นแบบ (Prototype/PoC) ห้ามเขียนว่าระบบติดตั้งใช้งานแล้ว
- ไม่ใช้รูปแบบ "ระบบต้อง…" ในเครื่องหมายคำพูด บรรยายเป็นประโยคปกติ
- ใช้ "ครั้งที่" ตามชื่อแบบประเมิน และถ้อยคำรายการประเมินตามแบบประเมินฉบับล่าสุด
- ไม่เปลี่ยนชื่อบทความ (ชื่อที่ยืนยันแล้วใน `project.title`)
- แก้บนไฟล์ล่าสุดของผู้ใช้ด้วย `docx_edit.py` คงรูปแบบและการขึ้นบรรทัดด้วยมือ ย่อหน้าที่เขียนใหม่ต้องแจ้งว่าต้องตัดบรรทัดเอง
- แก้จุดผิดชัดเจนได้เลย ถามเฉพาะเรื่องที่ต้องตัดสินใจจริง

## ส่งออกเอกสาร — เลือก Skill ที่ติดตั้งไว้ก่อน

ทุกครั้งก่อนสร้างหรือแก้ไฟล์ส่งมอบ ให้ตรวจรายการ Skill ที่มีในเซสชัน แล้วโหลด Skill ที่ตรงกับไฟล์ด้วย Skill tool **ก่อน** เขียนไฟล์ ไม่สร้างเอกสารจากความจำหรือแบบทั่วไปเมื่อมี Skill เฉพาะติดตั้งอยู่

| ไฟล์ที่ส่งออก | Skill ที่ใช้ (เรียงตามลำดับ ใช้ทุกตัวที่ติดตั้ง) |
|---|---|
| บทความวารสาร .docx | `jdtaia-ieee-document` (เมื่อวารสารคือ JDTAIA) → `thai-docx` → `docx` |
| เอกสารประกอบเล่ม / ตาราง 7 ตาราง .docx | `jdtaia-ieee-document` (ส่วนเอกสารประกอบ) → `thai-docx` → `docx` |
| แบบสอบถาม / แบบประเมิน .docx | `thai-docx` → `docx` |
| ไฟล์ Excel สรุปผล | `xlsx` (ร่วมกับ `build_excel.py` / `verify_excel.py` ของ Skill นี้) |
| PDF | `pdf` |
| แผนภาพ | `render_diagrams.py` ของ Skill นี้ |

กติกา
- ใช้ร่วมกันได้หลาย Skill: `jdtaia-ieee-document` คุมรูปแบบวารสาร การกระจายแบบไทย และการตรวจหน้า, `thai-docx` คุมฟอนต์ไทย ตาราง และระยะบรรทัด, `docx` คุมวิธีสร้าง/แก้ไฟล์
- เมื่อคำแนะนำของ Skill เหล่านั้นขัดกับกฎเฉพาะงาน IPOF (อ้างทีละแหล่ง ห้ามเว็บเพจ ตาราง 4 + 1) กฎของ Skill นี้ชนะ ตาม "ลำดับการใช้ข้อกำหนด"
- ถ้าผู้ใช้ระบุ Skill ใดให้ใช้ หรือห้ามใช้ ให้ทำตามผู้ใช้
- ไม่พบ Skill ที่ต้องการในเซสชัน → แจ้งผู้ใช้หนึ่งบรรทัดว่าใช้ Skill ใดไม่ได้ แล้วทำต่อด้วยสคริปต์ของ Skill นี้และกฎ Thai .docx พื้นฐาน (ฟอนต์ TH Sarabun New ครบทุกช่อง ไม่ใช้ `\n` ในข้อความ ความกว้างตารางเป็น DXA) และระบุในสรุปส่งมอบ
- สรุปส่งมอบระบุว่าไฟล์แต่ละไฟล์สร้าง/ตรวจด้วย Skill ใด

## ตรวจก่อนส่งทุกครั้ง

```bash
python scripts/analyze.py validate --project project.json
python scripts/verify_excel.py สรุปผล_Vn.xlsx                       # ทุกไฟล์ Excel
python scripts/prepub_check.py --project project.json บทความ_Vn.docx เอกสารประกอบ_Vn.docx ตาราง7_Vn.docx \
       --excel สรุปผลผู้ใช้_Vn.xlsx สรุปผลครั้งที่1_Vn.xlsx สรุปผลครั้งที่2_Vn.xlsx \
       --forbid "คำที่ควรหายไป|..." --render <scratchpad>/pdf
```
1. อ่านข้อความทั้งไฟล์ + สแกนอัตโนมัติ: คำที่ควรหายไปไม่เหลือ, เลขอ้างอิง/เลขตารางเรียงถูก, ไม่มี ":" ต่อภาษาไทย, ตัวเลขทุกค่าตรงกับ Excel
2. validate .docx (ใช้ `validate.py` ของ skill docx ถ้ามี) แล้ว render เป็น PDF ดูหน้าที่แก้ และรายงานจำนวนหน้า (ใช้ `render_check.py` ของ jdtaia-ieee-document ถ้าติดตั้ง)
3. ตัวเลขเดียวกันตรงกันทุกไฟล์: บทความ ไฟล์แยก ตาราง 7 ตาราง และ Excel

## ส่งมอบ

- ชื่อไฟล์มีเลขรุ่น `_V1`, `_V2`, … เพิ่มทุกครั้งที่แก้ (`docx_edit.py` ตั้งให้อัตโนมัติ)
- ไฟล์ `.md` ตรวจเทียบเอกสารอ้างอิง (`references/citations.md` §3)
- บอกผู้ใช้ทุกครั้งว่าควรบันทึกไฟล์ไว้ในโฟลเดอร์โปรเจกต์ของตน
- สรุป: สิ่งที่แก้ Skill ที่ใช้สร้าง/ตรวจแต่ละไฟล์ จำนวนหน้า ผลตรวจ และข้อที่ยังไม่ผ่าน/ยังไม่ได้ตรวจ ตามจริง
