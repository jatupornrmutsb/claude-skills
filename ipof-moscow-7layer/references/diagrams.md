# แผนภาพ (สร้างจาก project.json ด้วย render_diagrams.py)

ได้ไฟล์ HTML (แก้ข้อความ/สีได้) และ PNG ความละเอียดสูง (`--scale 3`) ทุกกล่องมีรหัสและระดับ MoSCoW **ฉบับสุดท้าย** และมีคำอธิบายสัญลักษณ์ M/S/C/W ระบุ "ระดับฉบับสุดท้าย" ช่วงใช้ "–"
แก้เนื้อหาที่ `project.json` แล้ว render ใหม่ ไม่แก้ PNG ตรง

## 1. กรอบ IPOF

| ส่วน | เนื้อหา |
|---|---|
| Input | ชุดข้อมูลนำเข้าจาก FR กลุ่ม G1 จัดกลุ่มตาม `data_type` |
| Process | การรับข้อมูลอัตโนมัติ / การตรวจคุณภาพและที่มา (NFR) / การวิเคราะห์ (FR กลุ่ม G2) |
| Output | ผลลัพธ์ของ FR ระดับ Must กลุ่ม G3 และ G4 |
| Feedback | การแจ้งปัญหาจากผู้ใช้ / การตรวจหลักฐานและแก้ข้อมูล / การบันทึกประวัติ |
| แถบกำกับ | สิทธิ์และการปกป้องข้อมูล (NFR ชั้น L6) ครอบทุกองค์ประกอบ |

กำหนดตำแหน่งเองด้วย `"ipof": {"part": "Feedback", "sub": "การบันทึกประวัติ"}` เมื่อกติกาอัตโนมัติไม่ตรง สคริปต์รายงานข้อที่ไม่อยู่ในกรอบ (ปกติ: G3/G4 ที่ไม่ใช่ Must)

## 2. สถาปัตยกรรม 7 ชั้น

L1 ผู้ใช้งาน, L2 การนำเสนอ, L3 บริการแอปพลิเคชัน, L4 วิเคราะห์ข้อมูล, L5 ข้อมูล, L6 ความมั่นคงและธรรมาภิบาลข้อมูล (แถบด้านข้างกำกับทุกชั้น), L7 โครงสร้างพื้นฐานและการเชื่อมต่อ

- G1 → L5, G2 → L4, G3 → L3, G4 → L2; NFR → L2/L6/L7 ตามลักษณะ
- ข้อกำหนดทุกข้ออยู่ในภาพ รวม Won't (กรอบเส้นประ) ข้อ Must ทุกข้อมีองค์ประกอบ (`component`) — สคริปต์ออก exit 1 ถ้าขาด

## 3. ภาพบริบทและภาพการไหลของข้อมูล

- บริบท (`context`): ผู้ใช้, แหล่งข้อมูลภายนอก, ข้อมูลที่แลกเปลี่ยน, ในขอบเขต/นอกขอบเขต
- การไหลของข้อมูล: Source → ตัวรวบรวมรายศูนย์พร้อมบัฟเฟอร์ → Validation → Transformation → Store → Processing → Output → Feedback/Logging ผูกข้อกำหนดด้วย `flow_stage`

## 4. ตารางตรวจสอบย้อนกลับ

Must → องค์ประกอบ/ชั้น → ข้อกำหนดที่พึ่งพา → กรณีทดสอบ TC-xx (HTML + CSV สำหรับวางลงเอกสาร)

## 5. ตรวจภาพก่อนส่ง

เปิด PNG ดูทุกภาพ: ข้อความไทยไม่ซ้อน กล่องไม่ล้น สีระดับอ่านออกเมื่อพิมพ์ขาวดำ (W ใช้เส้นประ) ฟอนต์ในภาพใช้ TH Sarabun New เมื่อเครื่องมี ไม่เช่นนั้นใช้ฟอนต์ไทยทดแทน — แจ้งผู้ใช้
